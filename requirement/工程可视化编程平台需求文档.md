# 工程可视化编程平台需求文档

版本：0.1.0  
日期：2026-05-27  
当前验证项目：`battery-flow`  
参考规格：`Graph Spec`、`Execution Spec`、`Node Authoring Spec`

## 1. 背景

工程计算场景中存在大量“计算书”类工作，例如泵计算、管道压降、设备选型、传热计算等。这类计算通常包含输入参数、公式推导、条件判断、单位换算、过程结果和最终输出。

传统 Excel 或脚本方式存在以下问题：

1. 计算逻辑和展示结果混在一起，难以复用。
2. 参数、公式、单位、结果来源不够结构化。
3. 复杂计算过程难以追踪和审核。
4. 相同计算模块难以封装成可复用组件。
5. 后续接入 AI 生成、计算书导出、节点库扩展时缺少统一模型。

本平台目标是构建一个面向工程计算的在线可视化编程工具。用户可以通过画布搭建计算图，编辑参数和公式，执行计算，并逐步沉淀领域节点和节点库。

## 2. 产品目标

当前阶段目标不是一次性实现完整 Grasshopper，而是验证工程计算平台的最小闭环：

1. 用 Graph JSON 表达工程计算模型。
2. 在画布上编辑节点、连线和布局。
3. 支持输入、公式、输出、领域节点四类核心节点。
4. 支持公式变量绑定和执行计算。
5. 支持领域节点通过内部子图表达可复用计算过程。
6. 支持保存和打开单个画布 JSON。
7. 以“泵计算书”为样例验证计算建模方法。

## 3. 用户角色

### 3.1 工程计算用户

负责输入工程参数、查看计算过程和输出结果。关注点是参数是否容易修改、结果是否可信、过程是否可追溯。

### 3.2 计算模板作者

负责把工程计算书建模成可复用 Graph。关注点是节点、公式、变量绑定、领域节点封装和保存打开。

### 3.3 节点开发者

负责开发领域节点、公式节点、未来 Python 节点或节点包。关注点是节点输入输出契约、单位量纲、执行接口和版本管理。

### 3.4 审核/校核人员

负责检查输入参数、公式来源、过程结果和最终输出。关注点是计算逻辑是否清晰、节点结果是否可定位、计算书是否可导出。

## 4. 当前 MVP 范围

当前 MVP 聚焦单画布编辑，不做多项目管理、用户权限、云端协作和完整计算书导出。

### 4.1 画布

画布用于展示和编辑当前 Graph。

已支持：

1. 单画布模式。
2. 新建画布。
3. 保存当前画布为 JSON。
4. 打开 JSON 并替换当前画布。
5. 节点拖动，并将位置写入 `graph.ui.layout`。
6. 节点连线，连线更新 `graph.edges`。
7. 删除节点和删除连线。
8. 右键节点显示操作菜单。

当前约束：

1. 打开 JSON 会替换当前画布，不做多画布切换。
2. 画布保存以浏览器下载 JSON 为主，尚未接入后端文件管理。
3. 当前主要验证桌面端使用体验。

### 4.2 左侧工具栏

左侧工具栏用于创建节点、执行计算和查看图概况。

已支持：

1. 新建画布。
2. 保存。
3. 打开。
4. 新增输入节点。
5. 新增公式节点。
6. 新增输出节点。
7. 选择合并节点。
8. 执行计算。
9. 展示图协议版本、节点数、边数、运行状态。

### 4.3 右侧面板

右侧面板分为三个 Tab：

1. 参数编辑。
2. 节点属性。
3. 输出结果。

设计原则：

1. 参数编辑用于全局查看和修改所有输入参数。
2. 节点属性用于编辑当前选中节点。
3. 输出结果用于查看最终输出和过程结果。
4. 节点操作不放在右侧面板中，统一放入右键菜单。

## 5. 节点需求

### 5.1 输入节点

输入节点用于表达用户可编辑的工程参数。

节点展示：

1. 节点名称。
2. 节点数值和单位。

节点属性：

1. 节点名称。
2. 编号。
3. 默认值和单位。
4. 量纲。

行为要求：

1. 输入节点只有一个默认输出，右键或变量绑定时不需要用户选择输出端口。
2. 修改输入参数后，下次执行计算应使用新值。
3. 输入节点可删除、复制。
4. 删除输入节点时，自动删除相关连线，并清理受影响公式节点的变量绑定。

### 5.2 公式节点

公式节点用于表达用户可编辑的普通表达式计算。

节点展示：

1. 节点名称。
2. 表达式，画布上以类 LaTeX 形式展示。

节点属性：

1. 节点名称。
2. 符号。
3. 表达式。
4. 输出单位。
5. 表达式变量绑定。

行为要求：

1. 用户可以在公式节点中输入表达式。
2. 系统从表达式中识别变量。
3. 变量必须绑定来源节点，执行时才能获得值。
4. 变量绑定可由连线自动生成。
5. 用户也可以在变量绑定区域手动选择来源。
6. 若来源节点只有一个输出，则自动使用该输出。
7. 若来源节点有多个输出，才显示“取值”选择。
8. 删除连线时，自动清理对应变量绑定。
9. 删除公式节点时，自动清理相关连线。
10. 公式节点可复制，复制后的公式节点不复制原变量绑定，避免误用旧来源。

当前约束：

1. 当前表达式引擎支持基础数学表达式。
2. 分段、求根、复杂程序逻辑暂不由普通公式节点承担。
3. 摩擦系数 `lambda` 当前仍由专门逻辑处理，未来可迁移到 Python 节点或专用求根节点。

### 5.3 输出节点

输出节点用于声明当前 Graph 的最终输出。

节点展示：

1. 节点名称。
2. 编号和单位。

节点属性：

1. 节点名称。
2. 编号。
3. 单位。
4. 取值来源。
5. 取值。

行为要求：

1. 输出节点可连接输入节点、公式节点或领域节点。
2. 当来源节点只有一个输出时，不显示“取值”选择。
3. 当来源节点有多个输出时，显示“取值”选择。
4. 输出节点结果显示在“输出结果 / 最终输出”中。
5. 输出节点可删除、复制。

### 5.4 领域节点

领域节点用于封装一组输入、公式和输出节点，形成可复用计算模块。

当前示例：

1. 入口管道阻力 `dP_s`。
2. 出口管道阻力 `dP_d`。

节点展示：

1. 节点名称。
2. 左侧输入接口。
3. 右侧输出接口。
4. 执行后展示关键输出值。

行为要求：

1. 领域节点在主画布上作为黑盒组件展示。
2. 主画布不直接编辑领域节点内部计算过程。
3. 右键领域节点可选择“展开内部子图”。
4. 双击领域节点也可进入内部子图。
5. 内部子图由输入接口、公式节点和输出接口组成。
6. 内部子图中可编辑参数、公式、变量绑定和输出来源。
7. 删除领域节点时，自动删除相关连线。
8. 领域节点复制暂不支持，后续按“复制子图/领域节点”单独实现。

## 6. 子图与合并需求

### 6.1 合并为领域节点

用户可以选择多个输入节点和公式节点，合并为一个领域节点。

已支持：

1. 进入合并选择模式。
2. 选择输入节点和公式节点。
3. 合并生成领域节点。
4. 内部生成子图。
5. 外部依赖转换为领域节点输入接口。
6. 对外结果转换为领域节点输出接口。

规则：

1. 至少选择一个输入节点和一个公式节点。
2. 被选公式依赖的来源若不在选择范围内，应提示用户补充选择。
3. 合并后主画布只保留领域节点。
4. 内部子图保留原计算逻辑。

### 6.2 展开内部子图

展开内部子图后，当前画布视图切换为领域节点内部。

需求：

1. 左侧标题显示当前为内部子图。
2. 提供返回主画布入口。
3. 内部子图可以执行计算。
4. 内部子图可以查看参数编辑、节点属性和输出结果。
5. 内部子图修改后，应同步回父级领域节点配置。

## 7. 连线与变量绑定

### 7.1 连线

连线表达节点之间的数据依赖。

需求：

1. 从来源节点输出连接到目标节点输入。
2. 输入节点单输出时，输出端口可在 UI 上弱化。
3. 多输出节点必须明确连接哪个输出。
4. 连线写入 Graph JSON 的 `edges`。
5. 删除连线时同步更新 Graph JSON。

### 7.2 变量绑定

变量绑定用于说明公式表达式中的变量从哪个来源节点取值。

示例：

表达式：

```text
H = (L2 - L1) + ((P2 - P1) + (dP_s + dP_d)) / (rho * g)
```

变量绑定说明：

1. `L2` 来自出口高度输入节点。
2. `L1` 来自入口高度输入节点。
3. `dP_s` 来自入口管道阻力领域节点的压降输出。
4. `dP_d` 来自出口管道阻力领域节点的压降输出。

需求：

1. 连线到公式节点时，优先绑定公式中已有且未绑定的变量。
2. 如果来源节点的编号与公式变量同名，优先绑定该变量。
3. 如果没有可匹配变量，可以生成新的变量名。
4. 用户可在节点属性中手动调整变量来源。
5. 删除来源节点或连线时，变量绑定自动清理。

## 8. 执行与结果

### 8.1 执行计算

点击“执行计算”后，执行当前 Graph。

需求：

1. 根据边构建依赖图。
2. 按拓扑顺序执行节点。
3. 对输入值进行单位换算。
4. 生成节点级运行结果。
5. 记录成功、错误、阻断等状态。
6. 更新画布节点上的结果预览。
7. 更新右侧输出结果。

当前能力：

1. 支持输入节点、公式节点、输出节点、领域节点执行。
2. 支持 `pipe.darcy_pressure_drop` 领域节点执行。
3. 支持内部子图执行并汇总对外输出。
4. 支持错误显示，例如变量未绑定、输出来源缺失。

### 8.2 输出结果

输出结果分为两类：

1. 最终输出。
2. 过程结果。

最终输出：

1. 优先展示输出节点的值。
2. 如果没有输出节点，可兜底展示末端公式节点。

过程结果：

1. 展示公式节点结果。
2. 展示领域节点关键输出。

## 9. 保存与打开

### 9.1 保存

需求：

1. 用户点击保存。
2. 系统提示输入画布名称。
3. 将当前 Graph 保存为 JSON。
4. 保存内容包括节点、连线、布局、子图配置。

### 9.2 打开

需求：

1. 用户点击打开。
2. 选择 JSON 文件。
3. 系统校验是否为有效 Graph。
4. 打开后替换当前画布。

当前约束：

1. 当前为本地 JSON 文件导入导出。
2. 不支持云端版本管理。
3. 不支持同时打开多个画布。

## 10. 泵计算书示例需求

平台当前以“泵计算书”为验证样例。

输入参数：

1. 物料流量 `Q`。
2. 物料密度 `rho`。
3. 物料粘度 `mu`。
4. 入口高度 `L1`。
5. 入口压力 `P1`。
6. 出口高度 `L2`。
7. 出口压力 `P2`。
8. 重力加速度 `g`。
9. 泵效率 `eta`。
10. 电机效率 `eta_m`。

领域节点：

1. 入口管道阻力 `dP_s`。
2. 出口管道阻力 `dP_d`。

公式节点：

1. 泵扬程 `H`。
2. 泵轴功率 `P`。
3. 电机功率 `P_m`。

输出节点：

1. 泵扬程。
2. 泵轴功率。
3. 电机功率。

验收要求：

1. 用户可以打开泵计算书画布。
2. 用户可以修改输入参数。
3. 用户可以执行计算并查看最终输出。
4. 用户可以展开入口或出口管道阻力领域节点，查看内部子图。
5. 用户可以保存修改后的画布 JSON。

## 11. 非功能需求

### 11.1 可追溯性

1. 每个结果应能追溯到来源节点。
2. 每个公式变量应能追溯到来源节点和输出端口。
3. 子图封装不应丢失内部计算结构。

### 11.2 可扩展性

1. 节点类型应通过节点注册表扩展。
2. 领域节点应支持由子图生成。
3. 未来应支持 Python 节点或其他编程语言节点。
4. Graph JSON 应保持可版本化。

### 11.3 易用性

1. 常用操作应在画布上完成。
2. 右键菜单用于节点操作。
3. 右侧面板用于参数和属性编辑。
4. 输出端口选择只在多输出来源时出现。
5. 参数列表应自然排列并支持滚动。

### 11.4 安全性

1. 未来用户代码节点必须运行在沙箱环境。
2. Python 节点默认不允许访问本地文件、网络和系统命令。
3. 节点执行必须有超时和错误隔离。

## 12. 当前不做

以下能力不进入当前 MVP：

1. 多画布同时打开与切换。
2. 云端项目管理。
3. 多人协同。
4. 权限体系。
5. 完整计算书 Word/PDF 导出。
6. 完整节点市场。
7. 完整 Python 包分发和远程内核调度。
8. 复杂表格节点。
9. 循环依赖和迭代流程自由编排。
10. 企业级领域节点版本治理。

## 13. 后续路线建议

### 13.1 第一阶段：编辑闭环完善

1. 连线删除交互优化。
2. 节点复制体验优化。已提供当前节点/多选电池组复制，后续可继续优化框选和粘贴位置。
3. 支持撤销/重做。已提供工具栏入口和 Ctrl+Z / Ctrl+Y 快捷键。
4. 支持画布自动布局。已提供 AI action 与助手工作流入口。
5. 支持节点搜索和快捷添加。已提供双击画布快捷添加。

### 13.2 第二阶段：领域节点产品化

1. 领域节点复制。已支持复制当前选中领域电池或多选电池组，并保留内部连线。
2. 领域节点保存为模板。已支持当前画布发布为平台计算书模板。
3. 模板插入画布。已支持套用平台计算书模板。
4. 领域节点输入输出接口编辑。已支持 Python 电池、公式电池和计算书章节的端口配置。
5. 子图版本管理。

### 13.3 第三阶段：执行能力增强

1. 完整单位和量纲校验。
2. 增量重算。
3. 执行日志。
4. 过程结果追踪。
5. 求根节点、条件节点、分段节点。

### 13.4 第四阶段：节点开发能力

1. Python 节点编辑器。已支持代码、端口和测试用例编辑。
2. Python 节点沙箱执行。已通过 Pyodide 和受限能力检查执行。
3. 节点包定义。已支持发布为平台 Python 算子草稿。
4. 节点测试用例。已支持本地测试用例和平台审核链路。
5. 节点版本升级策略。

### 13.5 第五阶段：计算书输出

1. 计算过程生成。已支持 Book Section 与 Book Assembler 编排。
2. 参数表生成。已支持 Field Table。
3. 结果表生成。已支持结构化结果、字段溯源和 Markdown 导出。
4. 公式引用和规范条文。已支持组件知识检索和章节模板承载。
5. Word/PDF 导出。当前提供 Markdown 计算书导出，Word/PDF 仍作为后续增强。
